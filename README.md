# G:\txt 工作区

长篇小说「整理 → 拆分 → 供 AI 分析 / 重写」的工作区，同时存放整合了拆分功能的月读阅读器源码。

根目录只放本 README、`.gitignore` 和下面列出的目录，不放数据文件或临时产物。

## 维护约定

- **新文件先归位再入库**：正文 → `novels\`；分析与统计 → `output\<书名>_分析\`；文档 → `docs\rules\` 或 `docs\research\`；脚本 → `tools\`。
- **根目录不留散文件**：只允许 README、`.gitignore` 和上面列出的目录；临时产物放 `tools\measure\`，或直接删。
- **`混沌冠冕_重写版\` 钉死在根目录**：它的 10 份档案把 `G:\txt\混沌冠冕_重写版` 写死为工作目录，移动/改名会断链，必须先改档案。
- **数据与产物不进版本库**：`novels\`、`output\`、`projects\reader\`、`.skill-patch\`、`_trash\` 均在 `.gitignore` 中。
- **删除先入 `_trash\`**：不直接删；按原相对路径镜像到 `_trash\<日期>-整理\`，写 `_MANIFEST.md` 记来源与体积，确认后再永久删（同盘移动不释放空间，确认删除才省空间）。

## 快速开始

```powershell
# 0) 【图形界面】双击 tools\novelkit\dist\NovelKit.exe（单文件，免装 Python）
#    命令行等价：.\tools\novelkit\dist\NovelKit.exe chai .\novels\混沌冠冕.txt

# 0b) 【推荐·脚本】一键拆书：原始 TXT → 分卷正文 + 机读统计 + 精读任务书
.\tools\chai\chai.ps1 -Input .\novels\混沌冠冕.txt
#    已拆好的目录只补统计：.\tools\chai\chai.ps1 -Input .\output\混沌冠冕

# 0c) 章节识别回归测试（改动解析逻辑后先跑，应 8/8 通过）
py -3 tools\novel_split\test_parser_regressions.py

# 1) 看小说文件的编码底细（不写盘）
py -3 tools\novel_split\novel_split.py probe novels

# 2) 拆分成多份 TXT（有卷按卷，无卷每份约 10 万字）
py -3 tools\novel_split\novel_split.py split novels --out output

# 3) 一条命令跑完 probe → analyze → split
py -3 tools\novel_split\novel_split.py all novels --out output

# 4) 只跑统计 / 对账 / 看词表
py -3 tools\chai\chai_stats.py stats output\混沌冠冕
py -3 tools\chai\chai_stats.py verify output\混沌冠冕
py -3 tools\chai\chai_stats.py terms output\混沌冠冕 --top-n 200

# 5) 运行月读（带拆分导出功能）
cd projects\reader
npm install
npm start
```

## 拆书产物怎么用

`tools\chai\chai.ps1` 一条命令产出四类中间产物，目的是让长篇**可以被分析**：

| 产物 | 位置 | 用途 |
|---|---|---|
| 分卷正文 | `output\<书名>\<书名>_第N部分.txt` | 每份约 10 万字，可整份喂给模型 |
| 结构索引 | `output\<书名>\00_目录索引.md` | 每份装了哪些章、起止章号、净字数 |
| 机读统计 | `output\<书名>_分析\stats_摘要.md` | 章长分布、段落与对话占比、章末钩型、高频术语首现章 |
| 精读任务书 | `output\<书名>_分析\精读任务书.md` | 把 N 份正文分配给 N 个 subagent 的固定作业单 |

**推荐用法**：先读 `stats_摘要.md` 拿到数据底座 → 按任务书派发逐章精读 → 最后汇总成总报告。
跨书对比时并排看各自的 `stats.json`，标准差、对话占比、短段占比的差异会直接说明
它们的写法有何本质不同（例如《混沌冠冕》章长标准差 476＝固定节拍器式，
《我在东京教剑道》1872＝弹性式）。

## 已知问题

### 1. 章节识别修了七个 bug（2026-11-15）

拆《这个巫师他就不科学》时暴露，随后在其余书与逐条验证中又查出四个：

| 现象 | 根因 | 影响 |
|---|---|---|
| 正文「序列之树，其上空……」被当成特殊章 | 特殊章短词「序」没要求边界 | 该书凭空多 44 个特殊章，前一章被截短 |
| 「第一百零二章 回归拉莫尔！」不算章 | 正则吃掉单位字后的空格，`_accept` 看不见分隔符，套用了「章回」黑名单 | 该书漏 102/220/442/505 共 4 章 |
| 「第二节车厢的前段……」算成第 2 章 | `节` 的黑名单没有「车」 | 该书多 1 个假「第 2 章」 |
| 标题里的「（求月票）」被广告规则整行删掉 | `AD_PATTERNS` 匹配「求月票/求订阅」，标题也被当广告 | 索引按标记计数、正文却没有这一章，统计侧永远少章（从纯血龙族 26 章、从全面战争 36 章） |
| 统计侧章数≠切分侧章数 | `chai_stats` 要求单位字后有分隔符，且没有散文闸门/目录闸门 | 无空格标题漏统计；「第一回战斗是……。」正文句被误算成章；书首目录块被当成章节 |
| 第 1917 章整章消失 | `_drop_toc` 假设输入按行号有序；「篇/集」标记追加在末尾，负行距被当成「≤2」，把相隔几十万行的标题串成假 run 整块删掉 | 《反派少爷》少 1 章 |
| 「【附录1.通用魔咒】」统计侧漏计 | 统计侧特殊章关键字后强制要求分隔符，切分侧不要求（反派少爷少 1 个特殊章） |

前四个与第六个在 `novel_split`，第五、七个在 `chai_stats`（已改成与切分侧同一套
关键字与判据：装饰剥离 → 散文闸门 → 章号/单位 → 复合词黑名单 → 目录块）。
回归测试 `tools\novel_split\test_parser_regressions.py` 现有 **8 个用例**（7 个端到端 +
1 个乱序目录块单元用例），并会校验「analyze 章数 == stats 章数」，防止两侧再次漂移。
