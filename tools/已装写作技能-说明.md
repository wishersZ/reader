## 为什么是「33 个目录 bundle + 每个内嵌 references」

DSH 的 `dsh-skill-filesystem` 只识别**深度 1**的两种形态：`<root>/<name>/SKILL.md` 或 `<root>/<name>.md`；
并且它把每个 bundle 的 `resourceBase` 设成**该 bundle 自己的目录**，加载时注入一行提示：
「Base directory for this skill: `<该目录>`，相对路径按此解析」。

而技能包源码里写的是 `references/xxx.md`，在原仓库里相对的是**仓库根**。
所以必须把共享的 `references/` 复制进**每一个**技能目录，相对路径才会落到正确位置。
这一点已实测：加载 `shuangdian` 时返回 `Base directory for this skill: C:\Users\Administrator\.dsh\skills\shuangdian`，
且 `shuangdian\references\trope-library.md` 存在可读。

## 更新 / 卸载

```powershell
# 更新到上游最新
& G:\story\tools\sync_webnovel_skills.ps1

# 只看会改什么
& G:\story\tools\sync_webnovel_skills.ps1 -DryRun

# 卸载（只删这 33 个目录，不动别的技能）
Get-ChildItem "$env:USERPROFILE\.dsh\skills" -Directory |
  Where-Object { $_.Name -in (Get-ChildItem G:\story\.skillstage\skills -Directory).Name } |
  Remove-Item -Recurse -Force
```

脚本会把上游仓库浅克隆到 `G:\story\.skillstage`（**用完可删，删了下次会重新克隆**），
再分发到 skill 根。它还会报告目标根里**不属于本包**的技能，不会误删。
