# 拆书流程（一键拆书）

> **一句话**：把一本原始网文 TXT，用一条命令变成「可直接喂给大模型的分卷正文 + 可复算的机读统计 + 分层精读任务书」，保证**零丢失、可对账、可重跑**。
>
> **来源**：这套流程是从《混沌冠冕》（645 章 / 287.6 万字）的实际拆解工作中固化下来的。本文既记录**方法论**，也记录**工具用法**与**踩过的坑**。

## 一、拆书到底在拆什么

拆书不是"把 txt 切开"，而是**把不可分析的原料变成可分析的中间产物**。一本 3 MB、600+ 章的网文，直接丢给模型有三个死结：

| 死结 | 后果 | 本流程的解法 |
|---|---|---|
| **超上下文** | 一次读不完，模型只能读开头和结尾，中间凭空编 | 切成每份约 10 万字，逐份精读 |
| **编码与排版脏** | GBK/UTF-8/BOM 混用、广告水印、章号缺重，解析出错 | 先无损统一编码，再规范化排版，再排序 |
| **无法累积结论** | 每次都要重新读原文，结论不可复算 | 机读统计落盘为 CSV/JSON，报告直接引用 |

所以拆书的目标是产出**四类中间产物**：

1. **干净的分卷正文**——每份约 10 万字，UTF-8、段首缩进统一、可直接整份喂给模型；
2. **结构索引**——每份装了哪些章、起止章号、净字数；
3. **机读统计**——章长分布、段落与对话占比、章末钩型、高频术语与首现章；
4. **精读任务书**——把 N 份正文分配给 N 个 subagent 的固定作业单。

**关键判断**：第 3 类（统计）是这套流程里最容易被忽略、但价值最高的一环。它让"这本小说节奏如何"从主观印象变成**可对账的数字**。例如《混沌冠冕》的章长标准差只有 476 字，而这个数字直接决定了它的写作方式（详见下文第五节）。

## 二、五阶段流水线

```
原始 TXT
   │
   ├─① probe    探测编码 / 换行 / BOM / 可解码候选        （不写盘）
   │
   ├─② encode   无损统一到 UTF-8 + CRLF，就地改写留 .bak
   │
   ├─③ analyze  分析卷/章结构，输出 Markdown 报告
   │
   ├─④ split    规范化 + 排序 + 切成每份约 10 万字
   │
   └─⑤ stats    机读统计 → chapters.csv / terms.csv / stats.json / stats_摘要.md
        │
        └─ 精读任务书.md → N 个 subagent 逐章精读 → 汇总总报告
```

### 各阶段做什么、为什么不能跳

| 阶段 | 做什么 | 为什么必须有 |
|---|---|---|
| **① probe** | 读文件头尾判断编码、BOM、换行、是否有零宽字符 | **只读先探**。不看底细就转码，可能把 UTF-8 当 GBK 解出乱码还"成功"写盘 |
| **② encode** | 无损统一编码；必须先能严格编码且回读一致才写盘 | 混编码会让后续所有统计都错。且**回读校验**能挡住杀软/磁盘干扰 |
| **③ analyze** | 识别卷/章结构，报告"发现 N 处章号逆序" | 先看清结构再切，避免把目录页当正文、把章号重置当乱序 |
| **④ split** | 规范化 + 排序 + 按卷或按字数切分 | 把 3 MB 变成 29 份约 10 万字，每份能进上下文 |
| **⑤ stats** | 逐章统计 + 全书汇总 + 术语发现 | 提供**可复算的数字底座**，让结论能被检验而不是拍脑袋 |

### 一个反复被验证的经验：章号"逆序"多半不是乱序

`novel_split.py` 在实测 7 本书上**一章都没有搬动**，因为所谓"逆序"实际是两种情况：

- **章号重置**：每卷从 `第001章` 重新开始（《我在东京教剑道》7 个卷全部如此）。全局按章号排序会把这本书彻底打乱 → 所以工具**按卷分组、组内排序**。
- **原书笔误 / 作者的话**：例如把 `第1119章` 插在 1020 章中间，或夹一句 `第三章正在码，凌晨弄完`。

**结论**：默认 `--sort auto` 只报告不搬动；确认真的乱了才用 `--sort force`，且搬动了哪些章会记进 `_排序调整.tsv`。

## 三、一键用法

### 最常用：一本原始 txt 一路跑到统计 + 任务书

```powershell
cd G:\txt
.\tools\chai\chai.ps1 -Input .\novels\混沌冠冕.txt
```

### 已经拆好的目录，只补统计

```powershell
.\tools\chai\chai.ps1 -Input .\output\混沌冠冕
```

### 批量处理整个目录

```powershell
.\tools\chai\chai.ps1 -Input .\novels
```

### 常用参数

| 参数 | 说明 |
|---|---|
| `-Path`（位置参数，别名 `-Input` / `-i`） | 原始 TXT、TXT 目录，或已拆好的 `output/<书名>` 目录 |
| `-Book` | 书名，默认从文件名推导 |
| `-Parts N` | 切成几份；不指定则按每份约 10 万字自动决定 |
| `-MaxChars N` | 每份净字数上限（与 `-Parts` 二选一） |
| `-OutRoot` | 产物根目录，默认 `<仓库根>\output` |
| `-Terms "亚伦,苏伦,莎尔"` | 人工确认的专名，强制进词表（避免被 n-gram 噪音淹没） |
| `-MinTermCount N` | 术语候选最低总频次，默认 15；词表噪音大就调高 |
| `-SkipEncode` | 跳过编码统一（源文件已是 UTF-8 时用） |
| `-DryRun` | 只预演不写盘 |
| `-TasksOnly` | 只重新生成精读任务书 |
| `-ShowProgress` | 显示每步实际执行的命令行与退出码（排查用） |

### 单独调用工具（不走一键脚本）

```powershell
# 机读统计
py -3 tools\chai\chai_stats.py stats output\混沌冠冕 --terms "亚伦,苏伦,莎尔"
# 对账
py -3 tools\chai\chai_stats.py verify output\混沌冠冕
# 只看词表
py -3 tools\chai\chai_stats.py terms output\混沌冠冕 --top-n 200 --min-count 20
# 底层拆分工具（五子命令：probe/encode/analyze/split/all）
py -3 tools\novel_split\novel_split.py split output\..\novels --parts 29 --out output
```

## 四、产物结构

```
output/
├── <书名>/                         ← ④ split 产出
│   ├── 00_目录索引.md              先看这个：每份装了什么、起止章号、净字数
│   ├── 01_章节清单.tsv             全部章节：序号/类型/卷/章号/标题/原行号/净字数
│   ├── manifest.json              机器可读清单（含校验结果）
│   ├── <书名>_第一部分.txt …       正文，UTF-8 / CRLF / 段首 2 个全角空格
│   ├── _已删除行.txt               被当广告删掉的行（可人工复核）
│   └── _排序调整.tsv               仅当排序真的搬动了章节时才生成
│
└── <书名>_分析/                    ← ⑤ stats 产出
    ├── stats_摘要.md              人读摘要，可直接粘进分析报告
    ├── stats.json                 机器可读全量统计
    ├── chapters.csv               逐章明细（21 列，含章末钩型与末句）
    ├── terms.csv                  术语候选：频次/首现章/出现章数/最高频章
    └── 精读任务书.md              派给 subagent 的作业单
```

**正文文件里不注入任何额外标记**（没有 YAML 头、没有分隔线），所以可以整份直接喂给模型，也可以随时和原文逐字对账。

## 五、机读统计：指标口径

> 口径写死在这里，报告里原样转述，保证**不同时间、不同人跑出来的数字含义一致**。

### 5.1 基本口径

| 指标 | 定义 |
|---|---|
| **净字数** | 把整行所有空白（含全角空格 U+3000）去掉后的字符数。与 `novel_split.py` 同口径 |
| **段落** | 正文里一个非空行 = 一个段落（拆分文件已规范化，无多行空行） |
| **含引号段落** | 含中文引号 `“ ” 「 」` 的段落，用于估算对话/吐槽占篇幅比 |
| **出场段落** | 某专名在该章出现的段落数（同段多次只算一次） |
| **首现章** | 该专名在全书中第一次出现的章号 |

### 5.2 章末钩型（六类，启发式）

| 代号 | 钩型 | 判据 |
|---|---|---|
| **A** | 对白收束钩 | 末句含中文引号 |
| **B** | 内心宣言钩 | 末句含"该/要/必须/决定/目标/由此而始"等决定类词 |
| **C** | 信息/悬念钩 | 末句以问号结尾，或含"原来/竟然/秘密/真相/为什么" |
| **D** | 危机/倒计时钩 | 末句含"小心/快跑/来不及/只剩/倒计时/降临/最后"等 |
| **E** | 收获/宣言钩 | 末句含"属于我/到手/拿下/封/登/成为/开始了/战吧"等 |
| **F** | 拟声/爆发钩 | 末句是叠字/拟声（啊啊啊、哈哈哈哈、BOOM） |
| **Z** | 其他/收束 | 以上都不命中 |

**重要**：这是**正则启发式**，不是人工判读。摘要文件里明确标注了这一点，并提示"抽样 20 章人工核对后再引用"。

**实测校验**（《混沌冠冕》645 章）：启发式给出 **A 对白收束 47.75%**，而人工逐章判读的既有报告给出 **引号收束 49.5%** —— 误差 1.75 个百分点，说明这套判据可用。Z 类（其他/收束）占 29.3%，是"末句平淡"的量化指标，本身就有诊断价值。

### 5.3 节奏指标

| 指标 | 算法 | 判读 |
|---|---|---|
| **单章均值 / 中位** | 全部章节净字数的均值 / 中位数 | — |
| **标准差 / 变异系数** | 总体标准差 / 均值 | **< 500 且 CV < 0.12 = 固定节拍器式**；> 1000 = 弹性式 |
| **每 50 章均字数** | 按 50 章分块求均值 | 检查章长是否随剧情强度波动 |

**为什么标准差是关键指标**：

- 《混沌冠冕》标准差 **476 字**（CV 0.107）→ **固定节拍器式**。作者不能靠"高潮章写长一点"制造高潮，**必须用内容密度替代篇幅**，这直接解释了它为什么必须章章留钩、频繁换场景。
- 《我在东京教剑道》标准差 **1872 字**，最长单章 12114 字 → **弹性式**。允许卷末/高潮章加长 2—3 倍。

**这一个数字就决定了两本书的写法差异**，而它只能靠机读统计得到。

### 5.4 段落与对话（手机屏优化程度）

| 指标 | 判读 |
|---|---|
| **平均段长** | 越短越适合手机阅读。《混沌冠冕》45.8 字 |
| **含引号段落占比** | 对话承担多少篇幅。《混沌冠冕》33.94%——**三分之一的篇幅靠对话推进** |
| **短段（≤12 字）占比** | "一句一段"的节奏重锤密度。《混沌冠冕》14.14% |
| **段落长度分布** | 六档：1-10 / 11-20 / 21-50 / 51-100 / 101-200 / >200 字 |

### 5.5 术语发现

纯 n-gram（2—6 字）+ 停用首尾字过滤 + 通用词黑名单 + **子串抑制**，不依赖分词库。

**子串抑制的必要性**：n-gram 会同时产出 `埃莉`(3147) 与 `埃莉诺`(3146)，两者频次几乎相同。必须按「长度降序 + 频次降序」处理，**只保留更长的完整专名**，否则短片段会挡掉长专名。

实测效果（《混沌冠冕》）：

```
原初恶魔亲王(120)  卡斯帕尔公爵(98)  阿斯摩蒂尔斯(89)
大龙龙埃吉尔(72)   萨利安九卷书(63)  卡尔萨斯魔盒(61)
白银圣母苏伦(54)   范格达海斯特(49)  科曼索大森林(47)
```

同时能筛出**意外有用的信号**：`哈哈哈哈哈哈`(301) 与 `啊啊啊啊啊啊`(74) —— 叠字拟声的高频出现直接指向情绪爆发的集中位置。

**局限**：仍会有重叠噪音（如 `埃诺奥克大沙` / `诺奥克大沙漠`）。所以需要 `-Terms` 传入人工确认的专名，且**词表只当候选，不当结论**。

## 六、从统计到结论：分层精读

统计给的是**数字底座**，结论还得靠读。10 万字级原料要靠 subagent 分工，所以 `chai.ps1` 自动生成 `精读任务书.md`，把 N 份正文转成 N 张作业单。

### 作业单要固定交付格式（否则无法汇总）

逐章：

```markdown
### 第N章 章名
- 情节：本章发生了什么（2—4 句，只写事实）
- 功能：本章在结构上干什么（铺垫/转折/高潮/结算/降温/换轨）
- 爽点：命中了哪几类（打脸/装逼/获取/升级/身份揭晓/收人/知识掠夺/建设/反派吃瘪）
- 章末钩：末句是什么，属于哪一类
- 金句：最值得记的 1—2 句原文（逐字摘录，标行号）
```

每份（卷）末额外写：情节链（要能看出"因为…所以…"）、功能定位、人物与关系变化、世界观新增、技法观察、可核查统计。

### 必须写进每个 subagent 的五条纪律

1. **只写读到的内容**，引用要能回到原文；不编造、不把推断写成事实。
2. **章号以正文标题为准**，不要自行重排。
3. **区分三类事实**：①文本明写的 ②可合理推断的（标注"推断"）③作者未交代的（标注"未交代"）。
4. **统计数字只引用 `stats_摘要.md`**，不要自己心算。
5. 读不完就如实说读到第几章，**不要用摘要冒充精读**。

### 主 agent 的汇总顺序

1. 先读 `stats_摘要.md` + `chapters.csv`（**数据底座**）
2. 再逐份读 subagent 笔记（人物/情节/技法）
3. 最后写总报告，建议结构：

```
定位与坐标系 → 宏观结构分期 → 情节与主线发动机 → 人物弧光
→ 世界观体系 → 叙事与写作风格 → 爽点配方与节奏规律 → 优点与缺陷 → 结论
```

4. **凡是结论都要能指回章号**；无法核查的标注"待验证"。

## 七、验证与对账（重要）

### 7.1 口径差异：一定要理解，否则会误判

`novel_split.py` 的 `manifest.json` / `00_目录索引.md` 里的「净字数」是**包含标题行与前置信息的全文净字数**；而 `chai_stats.py` 的 `total_chars` 是**章节正文净字数（不含标题行与前置信息）**。

二者的恒等关系是：

```
引擎正文净字数 + Σ(标题行净字数) + 前置信息净字数 == 索引/清单的全文净字数
```

《混沌冠冕》实测：

```
2,875,401  +  7,517  +  225  ==  2,882,918   ✔
```

`chai_stats.py verify` 就是按这个恒等式校验的。**它同时是一件很有用的事**：如果统计跑在了旧的拆分产物上，这里会直接对不上。

### 7.2 内容零丢失的三重校验

| 层 | 谁保证 | 怎么验 |
|---|---|---|
| **编码层** | `novel_split.py encode` | 回读比对字节与文本，不一致就报错 |
| **切分层** | `novel_split.py split` | 各份净字数之和 == 全文净字数，逐文件回读校验 |
| **统计层** | `chai_stats.py verify` | 正文 + 标题行 + 前置信息 == 索引全文净字数 |

### 7.3 报告里引用数字的规矩

- 统计数字**只从 `stats_摘要.md` / `stats.json` 取**，不要手算；
- 凡引用启发式结果（章末钩型），必须标注"启发式"并抽样核对；
- 区分**实测**（本工具跑出来的）与**引用**（别人报告里的），两者冲突时以能复算的一侧为准。

## 八、实现细节与踩坑记录

> 这一节是给维护者和将来改工具的人看的。每条都是实际撞过的坑。

### 8.1 Windows 上的 Python 编码（最容易踩）

本机 `python -c "import locale; print(locale.getpreferredencoding(False))"` 输出 **cp936**。后果：

- UTF-8 的 `.py` 源码若不写编码声明，可能被按 cp936 解读；
- `print()` 中文到控制台可能抛 `UnicodeEncodeError`（例如 `～` 在 cp936 下不存在）。

**对策**：所有 Python 文件**写 UTF-8 BOM**，并在任何入口（`chai.ps1`、命令行）设置：

```powershell
$env:PYTHONUTF8 = '1'
```

### 8.2 PowerShell 5.1 把原生 stderr 当致命错误

在 `$ErrorActionPreference = 'Stop'` 之下，被调用的原生命令只要往 stderr 写一行，PowerShell 就会抛 `NativeCommandError` 中断脚本——**即使该进程退出码是 0**。

实测 `2>$null` 与 `2>&1 | Out-Null` **都压不住**（错误记录已经生成）。

**对策**（本脚本采用）：改走 `cmd /c` 启动 Python，由 cmd 回传退出码，PowerShell 不再解析子进程 stderr。同时约定：**进度提示走 stdout，只有真正的错误走 stderr**；判定成功一律只看退出码。

### 8.3 Python 3.14 起 `\b?` 会报错

`re.compile(r"...\b?(.*)$")` 在旧版能跑，**Python 3.14 起抛 "nothing to repeat"**（`\b` 是零宽断言，后面不能跟量词）。而且 `\b` 对中文的边界语义本就不可靠。

**对策**：改用显式分隔 `(?:\s+|$|[：:、.．])`。

### 8.4 PowerShell 参数名不要用 `$Input`

`$Input` 是 PowerShell 的**自动变量**。把它当参数名会被覆盖成空值，`Resolve-Path` 随即报
`Cannot bind argument to parameter 'LiteralPath' because it is an empty string`。

**对策**：参数名用 `$Path`，保留 `-Input` 作为 `[Alias]`。

### 8.5 拆分文件的份间结构（曾经误判，记录在此）

`iter_parts()` 曾按**文件名字典序**排序，导致「第十部分」排在「第四部分」之前。已改为按**卷号数值**排序（解析中文数字，支持 `第十一部分` → 11）。

另外，早期版本曾假设「拆分点会把同一章标题重复写进相邻两份，前一份末尾是下一份首章的开头」，并据此做了跨份续接拼接。**该假设经实测被推翻**：

```
第七部分最后标题 = 第155章 苏伦之赐（下）
    其后 88 段以「月之海的传奇刺客恐惧利刃，接单！」结尾
第八部分第一行   = 第156章 妖精龙和雪精灵
    其后正文以「谷地历1361年2月初，胡雷克森林。」开头
```

两段文本**完全不同**——第 155 章确实在第七部分结束，第 156 章确实从第八部分开始，**没有任何内容被复制**。

最终正确口径就是最朴素的一种，并已在代码注释里写明，避免后来者重犯：

```
正文 = 某个标题行之后，直到【下一个标题行或文件结尾】
前置信息 = 每份文件第一个标题之前的内容，不计入正文统计
```

**前置信息要处理「每一份」，不能只处理第一份**（这个坑踩过一次）：7 卷本的书，每一卷文件开头都有卷标题与卷首语（`第一卷 化龙` 等）。早期版本只对第 1 份做前置处理，其余各份的卷首内容被静默丢弃，导致 41 字对不上账。修正后 7 本书全部对账通过。

### 8.7 章节标题格式必须容错

不同书的标题写法差异极大，已实测覆盖：

```
第1章 标题          第001章 标题       第一章 标题        第1章：标题
===第二百八十三章 石田的野心===        【第12章 标题】
序章 / 楔子 / 引子 / 前言 / 番外 / 终章 / 尾声 / 后记 / 完本感言
```

两个必要设计：

- **先剥首尾装饰字符**（`===`、`【】`、`☆★` 等），再做匹配。否则 `===第X章===` 这类会整个漏掉。
- **章号同时支持阿拉伯数字与中文数字**（`二百八十三` → 283）。中文数字解析算法与 `novel_split.py` 的同名函数保持一致，保证「切章」与「统计」两阶段识别出的章号完全相同。

### 8.6 数字对不上时的排查顺序

1. **先确认口径**：是不是"含不含标题行/前置信息"的差异（见 7.1）；
2. **再确认产物新鲜度**：`stats.json` 是不是跑在旧的拆分产物上（`verify` 会报）；
3. **定位到份**：按份比对「引擎净字数」与「该份非空行净字数 − 标题行净字数」，差在哪一份一目了然；
4. **最后才怀疑解析**：用 `--dump-markers` 看 `novel_split.py` 识别到的每一个标题行。

### 8.8 章节识别的六个坑（2026-11 修）

拆书时接连撞到六个，都会让「章数」和「正文」对不上：

1. **「序」误判**：`SPECIAL_HEAD_RE` 里 `序章|序言|序|楔子…` 后面的分隔符全是可选的，
   正文「序列之树，其上空……」被切成「序」+「列之树……」——一本书凭空多出 44 个特殊章，
   前一章还被截短。
2. **「章回」误杀**：`_accept` 的黑名单判断有同类毛病：正则把单位字后的空格吃掉了，
   `第一百零二章 回归拉莫尔！` 的 rest 以「回」开头，被当成「章回」复合词（漏 4 章）。
3. **「节车厢」误判**：反过来 `第二节车厢的前段……` 被当成第 2 章。
4. **标题被当广告删**：`AD_PATTERNS` 里有「求月票」「求订阅」，作者的章节名带
   `（求月票）` 时整行被删——索引仍按标记计数，正文里却没有这一章，于是统计侧
   永远比索引少（实测《从纯血龙族开始不做人》26 章、《从全面战争开始爆兵反清》36 章）。
   现在**标题行永不按广告处理**。
5. **目录闸门误删真章**：`_drop_toc` 假设 `found` 按行号有序，但「篇/集」歧义标记是
   `extend` 追加在末尾的；乱序时行距变成负数并被当成「≤ 2」，把相隔几十万行的标题
   串成一个假 run 整块删掉（《反派少爷》丢了第 1917 章）。现在先按行号排序，
   并显式要求 `0 <= gap`。
6. **特殊章漏统计**：`chai_stats` 的关键字后强制要求分隔符，`【附录1.通用魔咒】`
   在切分侧是 special-tail、统计侧却认不出（少 1 个特殊章）。现在两侧关键字
   （含 卷首语/登场人物/完结感言/特别篇/外传/附录…）与分隔符规则完全对齐。

另外修了**两侧口径漂移**：`novel_split` 接受「第10章三次初级兵种抽取」这种无空格标题，
`chai_stats` 却要求单位字后有分隔符，导致 stats 章数比索引少（《从全面战争开始爆兵反清》
少 51 章）。现在 `chai_stats` 用与 `novel_split` 同一套复合词黑名单。

回归测试：`tools/novel_split/test_parser_regressions.py`（8 个用例，含 1 个乱序目录块
单元用例；还会校验「analyze 章数 == stats 章数」，防止两侧再次漂移）。

**教训**：判据一旦依赖"单位字后有没有分隔符"，就必须从**原始行**取上下文，
不能用已被正则吃掉分隔符的捕获组；结构性标记（标题）不能被内容清洗规则删掉；
凡是「相邻/距离」判定，先确认输入真的是有序的。

## 九、已知局限

| 局限 | 说明 | 应对 |
|---|---|---|
| **章末钩型是启发式** | 正则判据，会有误判；Z 类（其他）占 29% 说明"末句平淡"很多 | 引用前抽样 20 章人工核对 |
| **术语表有噪音** | n-gram 会产出重叠片段，也会漏掉低频专名 | 用 `-Terms` 传人工确认的专名；调 `-MinTermCount` |
| **不依赖分词库** | 本机没有 jieba，所以用 n-gram 替代 | 需要更准的词表可另行安装分词库 |
| **术语 n-gram 上限 4 字** | 为性能把 n-gram 上限从 6 降到 4（中文专名绝大多数 ≤4 字） | 极少数 5 字以上专名可能漏；可用 `-Terms` 补 |
| **单章只读一次** | 统计是"文本表面"的，不含语义（如"这一章是否好看"） | 语义判断交给精读环节 |
| **按卷切分时各卷大小不均** | 实测 21 万 ~ 87 万字 | 某卷仍超上下文时，对该卷单独再跑 `--mode parts` |
| **不做繁简转换** | 工具只搬运算理，不改字 | 需要时另用转换工具 |
| **只处理 TXT** | EPUB/AZW3 需先转 TXT | — |

## 十、扩展到别的书

本流程对**任何中文长篇 TXT** 都适用，已实测 7 本书（含 GBK/UTF-8、有卷/无卷、100 万~1000 万字）。

上手前建议先跑一次探测，看清底细：

```powershell
py -3 tools\novel_split\novel_split.py probe .\novels          # 看编码/换行/BOM
py -3 tools\novel_split\novel_split.py analyze .\某书.txt --out output   # 看卷章结构
```

如果某本书的章节标题格式没见过，用 `--chapter-regex` / `--volume-regex` 传自定义正则（需含 `num`/`unit`/`rest` 命名组），或先用 `--dump-markers` 看看实际识别到了什么。

**跨书对比**是这套产物最有价值的用法之一：把两三本书的 `stats.json` 并排看，**标准差、对话占比、短段占比、钩型分布**的差异会直接告诉你它们的写法有什么本质不同——这正是《混沌冠冕》（固定节拍器，SD 476）与《我在东京教剑道》（弹性，SD 1872）的对比所展示的。
